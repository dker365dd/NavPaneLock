# .memo — 思考产物与上下文

这个目录记录项目里所有"想出来的东西"：技术决策、工作日志、踩过的坑、被否掉的方案。

**约定：以后每个项目根目录都要有 `.memo/`，用途统一。**

## 目录结构

```
.memo/
├── README.md          ← 本文件，说明约定
└── memory/
    ├── MEMORY.md      ← 长期有效的项目知识（技术决策、环境结论、约定）
    └── YYYY-MM-DD.md  → 每天的工作日志（append-only，只追加不覆盖）
```

## 各文件怎么用

| 文件 | 写什么 | 写法 |
|---|---|---|
| `memory/MEMORY.md` | 长期不变的东西：技术选型、环境实测结论、项目约定、用户偏好 | 提炼后更新，控制在 3k 字以内 |
| `memory/YYYY-MM-DD.md` | 当天干了什么：改了哪些文件、为什么这么改、实测结果、踩的坑 | **只追加**，不回头改写历史记录 |
| `README.md` | 目录用途说明 | 基本不用动 |

## 记什么

- **决策**：为什么选 A 不选 B，被否掉的方案是什么（以及为什么否）
- **实测结论**：跑出来的真实数据，别只记"应该可以"
- **踩的坑**：报错原文、根因、绕法 —— 下次遇到能直接抄
- **环境事实**：本机/目标环境的真实状态（版本、注册表现状、行为差异）
- **上下文**：做这个项目的原因、用户的原始需求与偏好

## 不记什么

- 密钥、令牌、账号密码
- 一次性的中间状态（临时路径、跑完就没的调试输出）
- 以后用不到的大段代码拷贝 —— 指向文件路径和行号即可

## 例子

`memory/2026-10-29.md` 里记录了右键菜单功能从设计到落地的全过程，
包括两个关键实测结论：Windows 自带那条 cmd 菜单项被 `HideBasedOnVelocityId` 藏在新版菜单之外；
`powershell.exe -WorkingDirectory` 参数被接受却不生效。
这两条都是踩过坑才定下来的，不写下来下次还会再踩。
